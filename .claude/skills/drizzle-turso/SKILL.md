# Database & Drizzle Guide (Turso / libSQL)

> Audience: future Claude agents and contributors working on data-layer code,
> one-off admin scripts, or schema changes. Read this before touching
> `src/lib/db/*`, writing a new script under `scripts/`, or running
> `drizzle-kit` commands.

---

## TL;DR

- **DB**: Turso (serverless libSQL/SQLite fork). Credentials live in
  `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` env vars.
- **ORM**: Drizzle, dialect `turso` (libSQL). Schema: `src/lib/db/schema.ts`.
  Client: `src/lib/db/client.ts` (lazy singleton — **never** import directly
  inside Next.js request handlers; use `getDb()`).
- **Migrations**: SQL files in `drizzle/`, applied manually. Schema is
  generated by `drizzle-kit` but `drizzle-kit push` is not used in CI.
- **One-off scripts**: live under `scripts/*.mjs`, use raw parameterized
  SQL via `@libsql/client`. See `scripts/seed-fresh-user.mjs` and
  `scripts/grant-grandmaster-demo.mjs` for templates.
- **Run anything that hits Turso**:
  `export $(grep -v '^#' .env | xargs) && node scripts/<your-script>.mjs`
- **Validate before committing DB code**:
  `pnpm tsc --noEmit && pnpm validate:content && pnpm test:run`.

## 1. When to use what

| You want to... | Use | Where |
|----------------|-----|-------|
| Read/write the DB from a Next.js API route or server action | `getDb()` from `@/lib/db/client` | `src/lib/db/client.ts` |
| Run a one-off admin/seed/migration script (e.g. backfill, fix, grant) | Raw `createClient({...})` from `@libsql/client` | `scripts/*.mjs` |
| Update the schema (add column, new table) | Edit `src/lib/db/schema.ts` → `drizzle-kit generate` → hand-edit `drizzle/NNNN_*.sql` | `drizzle/` |
| Pull/inspect a row in dev | `pnpm tsc --noEmit` + `tsx -e` snippet, or a script in `scripts/` | n/a |

**Don't** use `getDb()` from a script that runs via `node` — it depends on
`getServerEnv()` which throws if `TURSO_DATABASE_URL` is missing. Scripts
read the env var directly.

## 2. Repo architecture

### 2.1 Schema (`src/lib/db/schema.ts`)

Defines tables using Drizzle's `sqliteTable`:

```ts
import { sqliteTable, text, integer, index } from "drizzle-orm/sqlite-core"

export const users = sqliteTable("users", {
  id: text("id").primaryKey().$defaultFn(() => crypto.randomUUID()),
  email: text("email").unique(),
  // ...
  createdAt: integer("created_at", { mode: "timestamp" })
    .$defaultFn(() => new Date()),
})

export const sandboxSnapshots = sqliteTable("sandbox_snapshots", {
  id: text("id").primaryKey(),
  userId: text("user_id").notNull(),
  snapshotData: text("snapshot_data").notNull(), // JSON, see SandboxData
  totalXp: integer("total_xp").notNull().default(0),
  // ...
}, (t) => [
  uniqueIndex("sandbox_snapshots_user_id_unique").on(t.userId),
  index("sandbox_snapshots_total_xp_idx").on(t.totalXp), // leaderboard scan
])
```

**Conventions:**
- Timestamps: `integer("...", { mode: "timestamp" })` (Drizzle auto-converts
  to/from `Date` in JS land).
- Booleans: `integer("...", { mode: "boolean" })`.
- All IDs are `text` (UUIDs from `crypto.randomUUID()`).
- The "snapshot" pattern: a denormalized numeric column (`total_xp`,
  `current_streak`) sits next to a JSON blob (`snapshot_data`) so the
  leaderboard query can scan an index without parsing JSON. **Keep the two
  in sync** when writing.

### 2.2 Client (`src/lib/db/client.ts`)

Lazy singleton. Throws if `TURSO_DATABASE_URL` is missing.

```ts
import { getDb } from "@/lib/db/client"
const db = getDb()
const rows = await db.select().from(users).where(eq(users.email, "..."))
```

Why lazy: lets `next build` complete without a live DB.

### 2.3 Drizzle config (`drizzle.config.ts`)

```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
  schema: "./src/lib/db/schema.ts",
  out: "./drizzle",
  dialect: "turso",
  dbCredentials: {
    url: process.env.TURSO_DATABASE_URL!,
    authToken: process.env.TURSO_AUTH_TOKEN!,
  },
})
```

## 3. Common operations

### 3.1 SELECT (from a Next.js route)

```ts
import { eq, and, desc } from "drizzle-orm"
import { getDb } from "@/lib/db/client"
import { sandboxSnapshots, users } from "@/lib/db/schema"

const db = getDb()
const rows = await db
  .select({
    userId: users.id,
    totalXp: sandboxSnapshots.totalXp,
  })
  .from(users)
  .leftJoin(sandboxSnapshots, eq(sandboxSnapshots.userId, users.id))
  .where(and(eq(users.leaderboardOptIn, true), ne(users.id, MOCK_USER_ID)))
  .orderBy(desc(sandboxSnapshots.totalXp))
  .limit(20)
```

### 3.2 INSERT (Drizzle)

```ts
import { getDb } from "@/lib/db/client"
import { users } from "@/lib/db/schema"

const db = getDb()
const [created] = await db.insert(users).values({
  name: "Demo",
  email: "demo@example.com",
  leaderboardOptIn: true,
}).returning()

console.log(created.id) // UUID
```

### 3.3 UPSERT (Drizzle)

```ts
import { getDb } from "@/lib/db/client"
import { sandboxSnapshots } from "@/lib/db/schema"

const db = getDb()
await db
  .insert(sandboxSnapshots)
  .values({
    id: crypto.randomUUID(),
    userId: userId,
    snapshotData: JSON.stringify(sandbox),
    totalXp: sandbox.userStats.totalXp,
    currentStreak: sandbox.streakData.currentStreak,
  })
  .onConflictDoUpdate({
    target: sandboxSnapshots.userId,
    set: {
      snapshotData: JSON.stringify(sandbox),
      totalXp: sandbox.userStats.totalXp,
      currentStreak: sandbox.streakData.currentStreak,
      updatedAt: new Date(),
    },
  })
```

### 3.4 Querying a JSON column (Drizzle)

```ts
import { sql } from "drizzle-orm"
import { sandboxSnapshots } from "@/lib/db/schema"

const xp = await db
  .select({ xp: sql<number>`json_extract(${snapshots.snapshotData}, '$.userStats.totalXp')` })
  .from(sandboxSnapshots)
```

SQLite/Turso JSON helpers worth knowing:
- `json_extract(data, '$.path')` — get a value
- `json_array_length(json_extract(data, '$.arrayKey'))` — count array elements
- ❌ There is **no** `json_object_length` — count object keys in JS land

### 3.5 Transactions

```ts
import { getDb } from "@/lib/db/client"

const db = getDb()
await db.transaction(async (tx) => {
  await tx.insert(snapshots).values(...)
  await tx.update(users).set(...).where(eq(users.id, userId))
})
```

## 4. One-off scripts (the most common need)

### 4.1 Template

Save as `scripts/<name>.mjs`. Match the conventions in
`scripts/seed-fresh-user.mjs`.

```js
/**
 * @file <name>.mjs
 * @description One-line summary.
 *
 * Usage:
 *   export $(grep -v '^#' .env | xargs) && node scripts/<name>.mjs
 */

import { createClient } from "@libsql/client"
import { randomUUID } from "crypto"

if (!process.env.TURSO_DATABASE_URL) {
  throw new Error("TURSO_DATABASE_URL is not defined. Run: export $(grep -v '^#' .env | xargs)")
}

const client = createClient({
  url: process.env.TURSO_DATABASE_URL,
  authToken: process.env.TURSO_AUTH_TOKEN,
})

async function main() {
  // ...your work...
}

main().catch((err) => {
  console.error("❌ Failed:", err)
  process.exit(1)
})
```

### 4.2 Real example: `scripts/grant-grandmaster-demo.mjs`

Idempotently writes a fully-unlocked sandbox JSON for a user
(default: `saurabh22suman@gmail.com`):

```bash
export $(grep -v '^#' .env | xargs) && node scripts/grant-grandmaster-demo.mjs
```

Key patterns it demonstrates:
- **Discovering content from the filesystem** (no DB round-trip needed for
  the IDs that come from `src/content/`).
- **Maintaining a denormalized column + JSON blob in sync** (`total_xp`
  column + `userStats.totalXp` inside `snapshot_data`).
- **Upsert with SELECT-then-INSERT-or-UPDATE** (SQLite has `INSERT ... ON
  CONFLICT` too, but the explicit two-step is easier to read in scripts).
- **Self-verification** with a follow-up SELECT (Node-side JSON parse for
  object keys; SQLite for array lengths).

### 4.3 Env-var loading gotcha

`grep -v '^#' .env | xargs` strips comment lines and feeds the rest as
`KEY=VALUE` exports. **But** if any value contains a space or shell
metacharacter, this breaks. For production-style scripts, prefer:

```bash
set -a; source .env; set +a
```

## 5. Migrations

Schema is hand-edited, then SQL is generated by `drizzle-kit`, then
manually applied. **We do not run `drizzle-kit push` against production.**

### 5.1 Adding a column or table

```bash
# 1. Edit src/lib/db/schema.ts
# 2. Generate the migration
pnpm exec drizzle-kit generate
# 3. Inspect drizzle/NNNN_your_change.sql — add it to the file or hand-edit
# 4. Apply (use the dry-run step first if the change is destructive)
export $(grep -v '^#' .env | xargs)
pnpm exec drizzle-kit migrate   # uses drizzle.config.ts
```

### 5.2 Existing migrations

Look at `drizzle/0000_*.sql` through `drizzle/0009_*.sql`. The pattern
across the repo is to **hand-edit** the generated SQL when needed (e.g.
adding `IF NOT EXISTS` clauses to make scripts idempotent — see
`scripts/fix-db-constraints.mjs` and `scripts/run-migration.mjs`).

### 5.3 One-off schema fix (no migration file)

For a quick fix that doesn't justify a new migration, copy the pattern in
`scripts/fix-db-constraints.mjs`:

```js
import { createClient } from "@libsql/client"
const client = createClient({ url: process.env.TURSO_DATABASE_URL, authToken: process.env.TURSO_AUTH_TOKEN })

const migrations = [
  "CREATE UNIQUE INDEX IF NOT EXISTS 'foo_user_id_unique' ON 'foo' ('user_id');",
]

for (const sql of migrations) {
  try { await client.execute(sql); console.log("✓", sql) }
  catch (e) { console.log("✗", sql, e.message) }
}
```

## 6. Safety checklist before writing

1. **Read-only or write?** If write, run on a copy first or use a
   transaction with a follow-up `SELECT` to confirm.
2. **Scope**: does the script only touch the rows for the given user/email?
   Confirm with a `SELECT` before any `UPDATE`/`DELETE`.
3. **Idempotent?** Can you run it twice without breaking? Use
   `INSERT ... ON CONFLICT DO UPDATE` or SELECT-then-INSERT-or-UPDATE.
4. **JSON schema**: if writing to `snapshot_data`, the server does not
   validate; the client validates with Zod on load (see
   `src/lib/sandbox/types.ts`). Match the `SandboxData` shape exactly or
   the user will see "Invalid sandbox" errors next time they open the app.
5. **Env var presence**: throw a clean error at the top of the script if
   `TURSO_DATABASE_URL` is missing (see template).
6. **Verification**: end every script with a follow-up `SELECT` and
   `console.log` so the operator can eyeball the result.

## 7. Common gotchas

| Symptom | Cause | Fix |
|---------|-------|-----|
| `TURSO_DATABASE_URL is not defined` from `getDb()` | env not exported in shell | `export $(grep -v '^#' .env | xargs)` |
| `no such function: json_object_length` | SQLite/Turso doesn't have it | Count object keys in JS after `JSON.parse` |
| `no such function: leaderboard_opt_in` | Column missing on an old prod DB | See `try/catch` pattern in `src/app/api/leaderboard/route.ts` |
| "Invalid sandbox" on the client after a script write | JSON shape mismatch with `SandboxData` | Compare to `src/lib/sandbox/types.ts`; client validates with Zod on every load |
| `libsql` returns a row as `{id: "..."}` but Drizzle gives you `{ id: "..." }` with strict types | Drizzle inferred types from the schema | Use `InferSelectModel<typeof table>` for read shapes |
| Migration script ran twice and broke | Missing `IF NOT EXISTS` | Wrap statements in `IF NOT EXISTS` (or `IF EXISTS` for `DROP`) |
| `JSON.stringify` of sandbox is huge (10+ KB) and slow | Many `flashcardProgress` entries | Acceptable for a single user; for bulk writes, batch and stream |

## 8. Quick reference

```js
// env loading
export $(grep -v '^#' .env | xargs)

// libSQL client
import { createClient } from "@libsql/client"
const client = createClient({
  url: process.env.TURSO_DATABASE_URL,
  authToken: process.env.TURSO_AUTH_TOKEN,
})

// parameterized SELECT
await client.execute({
  sql: "SELECT id FROM users WHERE email = ?",
  args: [email],
})

// parameterized INSERT
await client.execute({
  sql: "INSERT INTO users (id, name, email) VALUES (?, ?, ?)",
  args: [id, name, email],
})

// parameterized UPDATE
await client.execute({
  sql: "UPDATE users SET name = ? WHERE id = ?",
  args: [name, id],
})

// JSON column
await client.execute({
  sql: `UPDATE sandbox_snapshots
        SET snapshot_data = ?, total_xp = ?
        WHERE user_id = ?`,
  args: [JSON.stringify(data), data.userStats.totalXp, userId],
})

// JSON length (array)
await client.execute({
  sql: "SELECT json_array_length(json_extract(snapshot_data, '$.achievements')) AS n FROM sandbox_snapshots WHERE user_id = ?",
  args: [userId],
})
```
