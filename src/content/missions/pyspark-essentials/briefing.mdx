# Mission Briefing: PySpark Essentials

## Situation Report

TechCorp's lakehouse pilot succeeded. Now the data team faces scalability challenges: the marketing team needs to analyze 5 billion user events. A Pandas script on a laptop crashed after 3 hours with out-of-memory error.

Traditional tools can't handle this volume: Pandas is single-threaded (~16GB limit), SQL on small clusters is slow for complex transformations, manual scripts take 100+ hours.

## Objectives
- Load 5 billion event records from Delta Lake
- Filter for specific event types (page_view, click, purchase)
- GroupBy user_id to aggregate behavior metrics
- Join with customer dimension table
- Write results back to Delta Lake
- Understand Spark's execution model (driver, executors, tasks)

## Key Intelligence
- **PySpark:** Python interface to Apache Spark for distributed processing across hundreds of machines
- **DataFrame API:** Similar to Pandas but distributed
- **Lazy evaluation:** Transformations (map, filter) are lazy; actions (count, show) trigger execution
- **Fault tolerance:** If a node fails, Spark recovers automatically

## Success Criteria
- DataFrame pipeline with 5+ transformations
- Lazy evaluation demonstrated (transformations vs actions)
- Distributed read/write from/to Delta Lake
- Performance understanding (partitions, shuffle, broadcast)
