# Mission Briefing: Data Ingestion Pipeline

## Situation Report

TechCorp's lakehouse is operational, but data sources are multiplying. They need to ingest from 12 different systems: application logs (JSON), customer databases (CDC/Parquet), clickstream events (CSV), and third-party APIs.

The current approach is manual Python scripts running on cron that re-process entire datasets, break when schemas change, and require 40+ hours/month of maintenance.

## Objectives
- Configure Auto Loader for JSON/CSV/Parquet files with incremental streaming
- Enable schema inference and evolution for evolving data sources
- Write data to bronze Delta tables
- Implement COPY INTO for batch historical loads
- Understand batch vs streaming tradeoffs

## Key Intelligence
- **Auto Loader:** Incremental streaming — processes only new files since last run; auto-detects column types; exactly-once semantics; scalable to 100K+ files/hour
- **COPY INTO:** Idempotent, SQL-based, simple syntax for batch ingestion — define schema explicitly

## Success Criteria
- Auto Loader pipeline running in streaming mode
- Schema inference handling evolving data sources
- Bronze tables populated with raw data
- COPY INTO used for historical batch load
