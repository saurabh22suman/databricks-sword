# Mission Briefing: Lakehouse Fundamentals

## Situation Report
You've joined **TechCorp's** data team as they migrate from a traditional warehouse to a **lakehouse**. The old stack can't keep up — queries that took 2 minutes last year now take 15, storage costs are climbing 30% per quarter, and schema changes take 3 weeks.

## Objectives
- Build a production-grade Delta Lake table for customer transactions
- Insert, update, and delete rows with ACID guarantees
- Query the data with sub-second latency
- Explain lakehouse architecture layers

## Key Intelligence
- **Delta Lake** adds ACID transactions, schema enforcement, and time travel on top of Parquet files in your data lake.
- The lakehouse pattern unifies data lake flexibility with warehouse performance — no more ETL duplication.
- Tables can be managed (Databricks controls files) or external (you control files via cloud URIs or Unity Catalog volumes).

## Success Criteria
- Working Delta table with proper schema
- All CRUD operations executed without error
- Aggregate query returns expected results
- Quiz confirms architecture understanding
